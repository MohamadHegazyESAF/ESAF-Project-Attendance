# مخطط الحضور والمواصلات — دليل التشغيل الكامل (النسخة الثانية)

نظام Online بأربع صلاحيات:

- **Developer (أنت)** — تحكم كامل: يضيف مستخدمين، يغيّر صلاحياتهم، يرفع بيانات
  الموظفين من إكسيل، ويشوف كل الواجهات.
- **Admin (الموارد البشرية)** — يحمّل قالب الإكسيل ويشوف تقرير المواصلات فقط.
- **Manager (المدير)** — يدخل حضور فريقه أسبوعيًا (الأحد للخميس).
- **Employee (الموظف)** — يشوف حضوره الأسبوعي وخط سيره فقط (قراءة بدون تعديل).

---

## لو الموقع شغال بالفعل (من النسخة الأولى)

اتبع الترتيب ده بالظبط:

### 1) شغّل ملف الترقية في Supabase

روح لـ **SQL Editor** في مشروعك على Supabase، افتح ملف `sql/migration_v2_roles.sql`
الموجود في هذا الحزمة، انسخه كامل، وقبل التشغيل:

- غيّر السطر:
  ```sql
  insert into profiles (email, role, name) values
    ('put-your-email-here@company.com', 'DEVELOPER', 'اسمك هنا')
  ```
  لإيميلك الحقيقي واسمك — ده هيخليك أول Developer في النظام.

ثم اضغط **Run**.

### 2) جيب مفتاح Service Role

روح لـ **Project Settings > API** في Supabase، وانسخ **service_role key**
(مختلف عن anon key اللي أخدته قبل كده — احذر متحطوش في أي مكان عام، ده مفتاح
كامل الصلاحيات على قاعدة بياناتك).

### 3) أضف المفتاح في Vercel

روح لمشروعك في Vercel → Settings → Environment Variables → أضف:

```
SUPABASE_SERVICE_ROLE_KEY = <القيمة اللي نسختها>
```

⚠️ **مهم:** اسم المتغير من غير `NEXT_PUBLIC_` في الأول — ده اللي بيخليه سري
وما يظهرش في المتصفح.

### 4) ارفع كل الملفات الجديدة والمعدّلة على GitHub

استبدل الملفات دي في الـ repository بتاعك بالنسخ الجديدة من هذه الحزمة:

```
app/page.js
app/manager/page.js
app/admin/page.js
app/admin/upload/page.js
app/employee/page.js        ← جديد
app/developer/page.js        ← جديد
app/api/create-user/route.js ← جديد
app/globals.css
```

(ارفعهم بنفس طريقة "Upload files" اللي استخدمتها أول مرة، بنفس الأماكن
والمجلدات بالظبط)

### 5) أعد النشر (Redeploy) من Vercel

Vercel هيبني تلقائيًا لما تحدّث GitHub، لكن لو محصلش، روح لـ Deployments
واضغط Redeploy يدويًا.

### 6) سجّل دخول بإيميلك

هتتوجّه تلقائيًا لصفحة **لوحة المطوّر** `/developer`.

---

## استخدام لوحة المطوّر

من صفحة `/developer` تقدر:

1. **تضيف مستخدم جديد**: إيميل + كلمة مرور مبدئية + صلاحية (Admin / Manager /
   Employee) → اضغط "إنشاء الحساب". النظام بيعمل الحساب فورًا بدون أي خطوة
   يدوية في Supabase.
2. **تغيّر صلاحية أي مستخدم موجود** من نفس الصفحة، من قائمة منسدلة جنب اسمه.
3. **تعاين باقي الواجهات** من الأزرار في الأعلى (شاشة المدير، تقرير المواصلات،
   رفع البيانات، شاشة الموظف).

---

## رفع بيانات الموظفين (بدل الإدخال اليدوي)

من صفحة `/admin/upload`:

1. اضغط **تحميل نموذج القالب** — هينزلّك ملف إكسيل فيه الأعمدة المطلوبة ومثال
   وورقة تعليمات.
2. املأ الملف ببيانات موظفيك الحقيقيين. الأعمدة:

   | العمود | إلزامي؟ | ملاحظة |
   |---|---|---|
   | رقم الموظف | نعم | فريد لكل موظف |
   | اسم الموظف | نعم | |
   | خط السير | نعم | لازم يطابق اسم خط موجود بالفعل في جدول routes |
   | الدرجة الوظيفية | نعم | White (إداري) أو Blue (تنفيذي) فقط |
   | البريد الإلكتروني للمدير المباشر | نعم | لازم يطابق حساب مدير مسجل بالفعل |
   | البريد الإلكتروني الخاص بالموظف | اختياري | لو موجود، الموظف يقدر يدخل بنفسه (بعد ما تنشئله حساب من لوحة المطوّر) |
   | الإدارة | اختياري | |
   | الحالة | اختياري | نشط (افتراضي) أو غير نشط |

3. ارجع لصفحة الرفع، اختر الملف، هيظهرلك عرض مسبق وأي أخطاء في الصفوف.
4. اضغط **تأكيد الرفع**.

هذه الميزة متاحة لصلاحية **Developer** فقط (Admin يقدر ينزّل القالب بس، حسب
طلبك). لو عايز الـ Admin يرفع البيانات هو كمان، قولّي وأعدّل صلاحية الرفع بسطر
واحد في قاعدة البيانات.

**ملحوظة مهمة:** لازم الخطوط (Routes) تكون موجودة في النظام الأول قبل رفع
الموظفين، لأن الرفع بيربط كل موظف بخط موجود بالاسم. لإضافة خط جديد حاليًا
استخدم Table Editor في Supabase مباشرة (جدول routes) — تقدر تضيفها كميزة
في لوحة المطوّر لاحقًا لو حبيت.

---

## تفعيل حساب موظف ليشوف بياناته بنفسه

1. تأكد إن عمود "البريد الإلكتروني الخاص بالموظف" متملي له في شيت الرفع.
2. من لوحة المطوّر، أنشئ له حساب دخول بنفس هذا الإيميل وصلاحية **Employee**.
3. هو كده يقدر يدخل ويشوف حضوره الأسبوعي وخط سيره.

---

## تغيير الأسبوع لـ الأحد–الخميس

اتعملت تلقائيًا في كل الشاشات (المدير، التقرير، الموظف) — الأسبوع دلوقتي بيبدأ
يوم الأحد وينتهي الخميس بدل السبت–الأربعاء.

---

## هيكل الصلاحيات في قاعدة البيانات

- جدول `profiles` — فيه إيميل كل مستخدم ودوره.
- الـ Developer بس يقدر يضيف/يعدّل صفوف `profiles`، `employees`، و `routes`.
- أي مستخدم مسجل دخول يقدر يقرأ بيانات الخطوط والموظفين والحضور (مطلوب
  للتقرير الإجمالي)، لكن التعديل محصور حسب الدور.
- المدير يقدر يعدّل حضور فريقه بس (حسب تطابق `manager_email`).

## هيكل الملفات (محدّث)

```
project/
  app/
    page.js                → تسجيل الدخول (بيوجّه حسب الصلاحية)
    developer/page.js       → لوحة المطوّر (مستخدمين وصلاحيات)
    manager/page.js          → شاشة المدير
    admin/page.js             → تقرير المواصلات
    admin/upload/page.js       → تحميل القالب + رفع البيانات
    employee/page.js            → شاشة الموظف
    api/create-user/route.js     → إنشاء حسابات جديدة (سيرفر)
    layout.js / globals.css
  lib/
    supabaseClient.js
  sql/
    schema.sql               → الأساس (شغّلته في النسخة الأولى)
    migration_v2_roles.sql     → الترقية دي (صلاحيات + حقول جديدة)
  .env.local.example
  package.json
```

## تطويرات مقترحة لاحقًا

- شاشة داخل لوحة المطوّر لإضافة/تعديل الخطوط (Routes) بدون Supabase.
- ربط تلقائي بين رقم الموظف وحساب دخوله بدل الاعتماد على تطابق الإيميل يدويًا.
- دمج الخطوط القريبة لتقليل عدد العربيات أكتر (Route Merging).
